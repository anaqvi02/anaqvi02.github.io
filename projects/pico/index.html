ORIGIN STORY

Why it exists.

Grade 12 computer engineering: my teacher taught machine code on an insanely old dev board you program with buttons, and at the same time I was messing around with a Pi Pico W. The gap between a raw chip you talk to by hand and a modern one you talk to from Python was an emulator waiting to exist, so I wrote it. In Python, which was the wrong tool, and therefore the right one.

HOW IT WORKS

The Core.

A fetch-decode-execute loop over the full Thumb-1 instruction set: 2-byte ops, ALU, branches, stack. The decoder and hot paths live in Cython, roughly 1000× faster than pure Python, with the semantics still expressed readably on top. Around the CPU sits an RP2040 model: memory map, CPU state, an ELF and raw-binary loader, and peripheral stubs for GPIO, UART, and USB.

HOW IT WORKS

Performance & Usage.

It sustains about 33 MHz of emulated clock, roughly 25% of a real chip, and the benchmark suite measures that directly so the number is a measurement, not a vibe. The API is small: load_program, set_pc, set_reg, run(cycles), get_reg, and the examples run hand-assembled Thumb-1 from a counting loop to a recursive factorial.
